# PRISM Acceptance Audit Workflow

Use when a project claims to be complete.

1. Clean checkout/state.
2. Fresh dependency install.
3. Fresh database.
4. Run migrations from zero.
5. Start API, worker, and frontend.
6. Run a real end-to-end lifecycle.
7. Verify security and tenant isolation.
8. Verify failure/recovery behavior.
9. Search for false-completion markers.
10. Trace requirements to implementation and meaningful tests.
11. Separate functional completion, verification completion, production readiness, and specification traceability.
12. Document every unexplained gap.
13. Declare complete only if the acceptance criteria are genuinely satisfied.
